# Architecture

**Analysis Date:** 2026-03-26

## Pattern Overview

**Overall:** Offline-First MVVM with Clean Architecture layering (Stacked framework)

**Key Characteristics:**
- Local SQLite database (Drift) is the single source of truth; UI streams live data from it
- Remote API writes are queued in a `SyncQueue` table and flushed asynchronously
- ViewModels are decoupled from Views via Stacked's `StackedView<VM>` / `ReactiveViewModel`
- Dependency injection is code-generated by Stacked's locator (`get_it` under the hood)
- Background sync runs in a separate Dart isolate via Workmanager every 15 minutes

## Layers

**UI Layer:**
- Purpose: Render state from ViewModels, forward user interactions
- Location: `lib/ui/views/`, `lib/ui/widgets/`
- Contains: `StackedView` subclasses (views), `ReactiveViewModel` / `BaseViewModel` subclasses, feature-scoped widget subfolders
- Depends on: ViewModels only (never touches repositories or DAOs directly)
- Used by: Nothing (top of call chain for the user)

**ViewModel Layer:**
- Purpose: Mediate between UI and domain/data; hold UI state; orchestrate navigation
- Location: `lib/ui/views/<feature>/<feature>_viewmodel.dart`, `lib/core/viewmodels/app_viewmodel.dart`
- Contains: `ReactiveViewModel` subclasses that subscribe to repository streams and expose state via getters + `notifyListeners()`
- Depends on: Repositories and Services (resolved via `locator<T>()`)
- Used by: Views

**Services Layer:**
- Purpose: Cross-cutting infrastructure concerns (connectivity, sync, database init)
- Location: `lib/services/`
- Contains: `ConnectivityService` (with `ListenableServiceMixin`), `SyncService` (with `ListenableServiceMixin`), `DatabaseService`
- Depends on: DAOs, `ApiClient`, `ConnectivityService`
- Used by: ViewModels (via reactive subscription), `main.dart`, Workmanager callback

**Repository Layer:**
- Purpose: Coordinate local database reads/writes with remote API calls; own sync-queue enqueuing
- Location: `lib/data/repositories/`
- Contains: `ProductsRepository`, `CategoriesRepository`; both implement interfaces from `lib/domain/repositories/`
- Depends on: DAOs (`lib/data/local/daos/`), `ApiClient`, domain models
- Used by: ViewModels

**Data / Local Layer:**
- Purpose: SQLite persistence via Drift ORM
- Location: `lib/data/local/`
- Contains: `AppDatabase` (`database.dart`), Drift `Table` definitions (`tables/`), `DatabaseAccessor` DAOs (`daos/`)
- Depends on: Nothing above it
- Used by: Repositories, `SyncService`, Workmanager callback

**Data / Remote Layer:**
- Purpose: HTTP communication with the DummyJSON REST API
- Location: `lib/data/remote/`
- Contains: `ApiClient` (Dio + retry interceptor), `ApiConstants`, `ProductDto` / `CategoryDto` (Freezed + json_serializable)
- Depends on: Nothing above it
- Used by: Repositories, `SyncService`

**Domain Layer:**
- Purpose: Shared business models and repository contracts
- Location: `lib/domain/`
- Contains: Freezed immutable models (`Product`, `ProductCategory`, `SyncOperation`), `SyncStatus` enum, abstract repository interfaces (`IProductsRepository`, `ICategoriesRepository`)
- Depends on: Nothing (pure Dart)
- Used by: All layers

## Data Flow

**Read Flow (UI displays products):**

1. `ProductsView` builds a `ProductsViewModel` via Stacked
2. `onViewModelReady` calls `viewModel.initialize()`
3. ViewModel subscribes to `ProductsRepository.watchProducts()` stream
4. `ProductsRepository` maps the Drift `watchAllProducts()` stream through `_toDomain()` to emit `List<Product>`
5. On emission, `_onProductsChanged()` sets `_products` and calls `notifyListeners()`
6. View rebuilds via `ReactiveViewModel` → `builder()` renders `ProductCard` widgets

**Write Flow (create product offline):**

1. User submits form in `AddProductView` → ViewModel calls `ProductsRepository.createProduct()`
2. Repository writes product to `Products` table with `syncStatus = 'pending'`
3. Repository enqueues a `create` operation to `SyncQueue` table
4. Drift stream fires; UI updates immediately (optimistic)
5. When connectivity is available, `SyncService.syncAll()` processes the queue
6. On success, `productsDao.updateRemoteId()` stamps the remote ID and sets `syncStatus = 'synced'`

**Background Sync Flow:**

1. Workmanager wakes `callbackDispatcher` in a fresh isolate every 15 minutes (requires network)
2. Isolate constructs its own `AppDatabase`, `ApiClient`, `ConnectivityService`, `SyncService`
3. `syncService.syncAll()` processes all pending queue entries
4. Database is closed before isolate exits to prevent WAL corruption

**State Management:**
- ViewModels use `ReactiveViewModel.listenableServices` to auto-rebuild when `ConnectivityService` or `SyncService` emit via `notifyListeners()`
- `ReactiveValue<T>` inside services acts as a thin observable wrapper
- Streams from Drift DAOs propagate DB changes in real time to all active subscribers

## Key Abstractions

**`IProductsRepository` / `ICategoriesRepository`:**
- Purpose: Contracts that decouple ViewModels from concrete repository implementations
- Location: `lib/domain/repositories/i_products_repository.dart`, `lib/domain/repositories/i_categories_repository.dart`
- Pattern: Abstract class with method signatures only; concrete impl in `lib/data/repositories/`

**Drift DAOs:**
- Purpose: Typed, composable SQL queries bound to a single table
- Examples: `lib/data/local/daos/products_dao.dart`, `lib/data/local/daos/sync_queue_dao.dart`
- Pattern: `@DriftAccessor(tables: [T])` class extending `DatabaseAccessor<AppDatabase>`; streams returned for watch queries

**Freezed Domain Models:**
- Purpose: Immutable value objects with `copyWith`, equality, JSON serialisation
- Examples: `lib/domain/models/product.dart`, `lib/domain/models/category.dart`
- Pattern: `@freezed abstract class Foo with _$Foo` + `part 'foo.freezed.dart'; part 'foo.g.dart';`

**SyncQueue:**
- Purpose: Durable outbox for mutations made while offline
- Table: `lib/data/local/tables/sync_queue_table.dart`
- Pattern: Repository enqueues on write; `SyncService` dequeues and applies to API; retry count tracked; up to 3 retries before marking `failed`

**`ListenableServiceMixin`:**
- Purpose: Enables services to notify reactive ViewModels without direct coupling
- Usage: Both `ConnectivityService` and `SyncService` mix this in and call `notifyListeners()`; ViewModels declare them in `listenableServices`

## Entry Points

**App Entry Point:**
- Location: `lib/main.dart`
- Triggers: Flutter `runApp()`
- Responsibilities: Bootstrap order — locator, database, API client, repositories, connectivity, sync service, Workmanager registration, initial remote data fetch (silent failure if offline)

**Background Entry Point:**
- Location: `callbackDispatcher()` in `lib/main.dart` (annotated `@pragma('vm:entry-point')`)
- Triggers: Workmanager periodic task `'offline-first-sync'`
- Responsibilities: Isolated sync of pending queue entries; always closes DB on exit

**Route Root:**
- Location: `lib/app/app.dart` (`@StackedApp` annotation)
- Generated files: `lib/app/app.router.dart`, `lib/app/app.locator.dart`
- Initial route: `MainView` at `/`

## Error Handling

**Strategy:** Silent failures with UI state feedback

**Patterns:**
- Network errors during initial fetch or refresh are caught and swallowed; local cached data is served instead
- `SyncService` catches per-operation errors, marks the queue entry `failed`, and sets `syncStatus = 'failed'` on the product after 3 retries
- ViewModels surface loading/error state via Stacked's `isBusy` / `modelError` (base class `AppViewModel` wraps these)
- Connectivity status is shown in a banner widget (`ConnectivityBanner`) and syncing indicator in the header

## Cross-Cutting Concerns

**Logging:** Not implemented — errors are silently swallowed at repository and ViewModel level
**Validation:** Light form validation in `AddProductView` / `EditProductView` ViewModels; no shared validator abstraction
**Authentication:** Not implemented — DummyJSON API requires no auth token
**Dependency Injection:** Stacked locator (`get_it`-backed); singletons registered manually in `main()` after `setupLocator()`; lazy singletons for navigation/dialog/snackbar services generated by `stacked_generator`
